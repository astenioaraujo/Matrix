# Matrix — contexto de projeto

Resumo operacional para o Claude Code. A especificação funcional completa do módulo Saldos (regras de negócio, mockups, decisões) está em `docs/spec_saldos_matrix.md`.

## O que é

Matrix é um sistema de análise de dados para uma rede de postos de combustível, multi-tenant (`cod_empresa`). Módulos: Financeiro, Operações, Vendas, RH, Vistorias, Performances, Treinamentos, Compliance, Configurações, Usuários, Canivete Suíço e Projetos.

- Empresas: `EMP010` (Lucena), `EMP011` (Vilela), `EMP011ADM`, `EMP012` (30 Set CZ)
- Banco: PostgreSQL via Supabase
- Autenticação: **custom**, não é Supabase Auth — tabela própria `usuarios` com `senha_hash`. Não existe `auth.uid()`.
- Controle de acesso: `usuarios_empresas` (empresa) + `usuarios_filiais` (filial) + `usuarios_permissoes` (ação/tela, ligada a `permissoes_catalogo`) — checado na API, não em RLS por linha. Superusuário faz bypass em tudo.
- RLS nas tabelas novas: só para bloquear acesso direto via chave anônima; a API usa a **service role key**.

## Convenções do schema (seguir sempre)

- PK: `id_<entidade>` inteiro, `GENERATED BY DEFAULT AS IDENTITY`
- Toda tabela carrega `cod_empresa character varying`
- Filial é referenciada por `(cod_empresa, cod_filial)` — **nunca** por um `filiais.id` interno
- Área é referenciada por `id_area integer` (FK para `areas.id_area`)
- Status/tipo: `character varying` livre, não enum do Postgres
- Auditoria: `criado_em` / `atualizado_em` (`timestamp without time zone`, default `now()`)
- `ordem integer default 10`
- Nada de subtotal/total/diferença/variação como coluna — sempre calculado na consulta, nunca persistido

## Infra

- **Conexão por requisição** (`db.py`): abrir conexão com o banco remoto custa ~600 ms, muito mais que as consultas. `get_connection()` devolve a **mesma** conexão para todos os chamadores dentro de uma requisição Flask e ignora `close()` (as ~210 chamadas espalhadas fazem `finally: conn.close()`). Quem fecha de verdade é o teardown em `app.py`. Fora de requisição (scripts, cron) abre uma nova.
- **Ícones de atalho no topo** (`app.py`, context processor `_injetar_atalhos_topo`): roda em TODA página que estende `base.html`. As permissões saem de **uma consulta só** e ficam em cache na sessão, amarradas a `(id_usuario, cod_empresa)`. Ao acrescentar um ícone novo, incluir a opção na mesma consulta — não criar outra.

## Como testar sem navegador

Não há suíte automatizada. O que funciona bem:

- **Requisição autenticada**: gerar cookie de sessão assinado e usar `curl`.
  ```python
  from flask.sessions import SecureCookieSessionInterface
  import app as m
  s = SecureCookieSessionInterface().get_signing_serializer(m.app)
  print(s.dumps({'id_usuario':2,'tipo_global':'superusuario','cod_empresa':'EMP010','nome_empresa':'X','nome_usuario':'Y'}))
  ```
  Usar `curl -L` quando a rota puder redirecionar por falta de permissão — sem isso o cabeçalho nem chega a ser renderizado e o teste engana.
- **Lógica de JavaScript**: extrair as funções do HTML servido e rodar em JavaScriptCore (`osascript -l JavaScript`), com stubs de `document`/input. Foi assim que os bugs de digitação da tela de Saldos foram reproduzidos e comprovados.
- O servidor de desenvolvimento roda em `localhost:5001` em modo debug (recarrega sozinho a cada alteração).

# Módulo Financeiro

## Saldos (conciliação diária banco × sistema)

Primeiro item do menu do Financeiro. Tabelas em `migrations/criar_tabelas_saldos.sql`: `contas_bancarias`, `indicadores_recebiveis`, `competencia_mes`, `saldos_bancarios`, `saldos_recebiveis`, `valores_informados`.

- `contas_bancarias` e `indicadores_recebiveis` são cadastros **por empresa**, não por área — todas compartilham o mesmo conjunto; filial que não usa lança zero.
- Os saldos referenciam o cadastro por FK, **não** valores fixos em código — o cadastro define as linhas da tela.
- Variação dia a dia vale para qualquer conta/indicador cadastrado, nunca lista fixa. Calculada **em Python** (não `LAG`) — ver bug abaixo.

**Permissões** (`permissoes_catalogo`, sistema `FINANCEIRO`): `MENU_SALDOS` 505, `CONSULTA_SALDOS` 506, `LANCAMENTO_SALDOS` 507, `CADASTRO_CONTAS_BANCARIAS` 508.

**Endpoints** (`routes/financeiro_routes.py`, seção "SALDOS"): CRUD de `contas-bancarias`, `indicadores-recebiveis`, `competencias`; `GET /api/saldos`; 3 upserts em lote (`PUT /api/saldos/bancarios`, `/recebiveis`, `/valores-informados`); `GET/POST /api/usuarios-areas-saldos` + `DELETE /<id>`; `GET/POST /api/saldos/liberacao-temporaria`.

**Telas**:
- `templates/saldos.html` — seletor de área (só as liberadas), chips de período, setas ← → que deslocam o par de datas em 1 dia, 3 modos (Bancos/Sistema/Lado a lado, cabeçalho azul/roxo), blocos por dia em grid estilo Excel (mesmo padrão de `matricial.html`: `table-layout: fixed`, colgroup fixo, primeira coluna congelada, mapa de calor). Variação e Valores Informados **só no modo Bancos**. No Lado a lado, divergência banco×sistema pinta as **duas** células de vermelho vivo. Botão "Duplicar de Anteontem" aparece só no card de ontem, e só quando o bloco de ontem está zerado e o de anteontem tem valor.
- `templates/configurar_saldos.html` — **menu** de configuração, em `Financeiro → Saldos → Configurar Saldos`. Uma página por opção: Períodos de Apuração (`saldos_periodos.html`), Feriados (`saldos_feriados.html`), Parâmetros de Visualização (`saldos_parametros_visualizacao.html`), Contas Bancárias (`saldos_contas_bancarias.html`), Indicadores de Recebíveis (`saldos_indicadores_recebiveis.html`), Liberação Temporária (`saldos_liberacao_temporaria.html`), todas sob `/saldos/configurar/...`. As três últimas ficavam em `Financeiro → Cadastros` (`cadastro_saldos.html`, removido); Acesso por Área virou item do próprio menu de Saldos (`acessos_area_saldos.html`). Períodos, Feriados e Parâmetros de Visualização exigem `CONFIGURAR_SALDOS`; as outras três, `CADASTRO_CONTAS_BANCARIAS` — o menu abre com **qualquer uma** das duas e só mostra o que o usuário pode.

**Acesso por área**: tabela `usuarios_areas_saldos`. **Só o acesso à área basta** — não depende de `usuarios_filiais`. Quem tem a área vê/lança em todas as filiais dela. Gerenciado atrás de `CADASTRO_CONTAS_BANCARIAS` (decisão do cliente, não é exclusivo de superusuário). Funções-chave: `areas_permitidas_usuario()`, `filiais_permitidas_usuario()`, `cod_filiais_permitidas_lancamento()`.

**Só dias úteis**: a tela não gera sábado, domingo nem feriado. A variação encosta cada dia útil no **dia útil anterior** (sexta ← segunda; feriado no meio é pulado). Feriados ficam em `saldos_feriados` (`migrations/criar_tabela_saldos_feriados.sql`), cadastrados em **Saldos → Configurar Saldos → Feriados** (`templates/saldos_feriados.html`) (`GET /api/saldos/feriados` liberado para `CONSULTA_SALDOS`; POST/DELETE exigem `CONFIGURAR_SALDOS`). Helpers no backend: `carregar_feriados`, `eh_dia_util`, `dia_util_anterior`; no JS de `saldos.html`: `ehDiaUtil`, `diaUtilAtras`, `deslocarDiasUteis` (chips e setas ← → andam em dias úteis). O título de cada bloco mostra `04/08/2026 - Terça-feira`. A consulta busca só as datas necessárias (`data = ANY(...)`), incluindo o dia útil anterior que pode cair fora do período. **Consultar Variações e Variações por Filial** também: `_coletar_variacoes` só aceita dia útil como ponta do comparativo (existem lançamentos em sábados/domingos no histórico — sem esse filtro uma ponta cairia neles).

**Parâmetros de visualização por empresa**: `saldos_configuracoes` (`migrations/criar_tabela_saldos_configuracoes.sql`), uma linha por empresa, uma coluna `mostrar_*` por bloco de `saldos.html` — `mostrar_recebiveis` (Estoques e Recebíveis; junto com ele some a linha de TOTAL, que soma os dois blocos), `mostrar_variacoes`, `mostrar_valores_informados`. Todos ligados na EMP010, desligados nas demais; empresa sem linha = tudo desligado. Desmarcar só esconde — nada é apagado. A lista de colunas fica em `OPCOES_VISUALIZACAO_SALDOS`; ao acrescentar uma opção, incluir aí (leitura, gravação e SQL são montados a partir dela) e tratar a constante correspondente no JS. Lido por `config_saldos_empresa()` e gravado em `PUT /api/saldos/configuracoes`, que **grava a linha inteira** — a tela manda sempre o estado de todos os checkboxes (ambos `CONFIGURAR_SALDOS`).

**Trava de datas**: só dá para lançar/editar os **dois últimos dias úteis** (numa segunda-feira, sexta e quinta — antes eram dias corridos, o que numa segunda liberava sábado e domingo, dias que a tela nem gera mais). Um usuário com `CADASTRO_CONTAS_BANCARIAS` pode liberar temporariamente uma data mais antiga na aba "Liberação Temporária"; a liberação **expira sozinha em 1 hora**, checada por horário (`saldos_liberacao_temporaria.ativado_em`), sem rotina em background. A trava real está nos 3 endpoints de lançamento (403), não só na tela.

**Importar valores de estoque (Operações → Saldos)**: as linhas de recebíveis marcadas com `indicadores_recebiveis.origem_estoque` (`COMPRA`, `TRANSITO`, `ESTOQUE` — na EMP010, "Compra Combustível", "Em Trânsito" e "Estoque") ganham um botão **Importar** na coluna TOTAL, só no modo Bancos e em dia editável. Ele puxa os mesmos números da **Consulta de Estoques** (`compras_rs`, `transito_rs`, `estoque_atual_rs`, lendo o relatório de estoques do **dia seguinte** ao saldo — o saldo do dia 10 fecha com a tela de estoques do dia 11, que traz a medição da manhã do 11 e as compras/trânsito do próprio dia 10), por filial da área. Condições: **tudo** precisa estar bloqueado em Operações **até** a data (não só ela — um dia aberto lá atrás ainda muda compras e trânsito; a varredura é `datas_bloqueio_pendentes`, que para nos 10 dias do bloqueio automático em vez de percorrer o histórico) e a linha precisa estar **zerada** (não sobrescreve digitação). Depois de importar, os campos ficam travados e o botão vira **Desfazer importação**, que zera a linha e libera de novo. Tabelas: `saldos_importacoes_estoque` (uma linha por empresa/data/área/indicador) e a coluna nova em `indicadores_recebiveis` (`migrations/criar_importacao_estoque_saldos.sql`). Endpoints `POST/DELETE /api/saldos/importar-estoque` (`LANCAMENTO_SALDOS`). A trava de edição de linha importada também vale em `PUT /api/saldos/recebiveis` (403), não só na tela.

**Carga histórica (Junho/26)**: `migrations/seed_saldos_junho26.sql`, gerado de duas planilhas reais (Área I - Thalyta, Área II - Carol). Rodar **depois** de `criar_tabelas_saldos.sql`. Faltam os dias **30 e 31/05/2026** (gap real; precisaria das planilhas originais para reprocessar).

### Bugs corrigidos em Saldos (não reintroduzir)

- **Variação zerada quando falta lançamento (2026-07-03)**: era `LAG()` sobre as linhas existentes — filial sem lançamento no dia era pulada, e a ausência virava `0.0`, escondendo variação real. Agora `montar_bloco_dia` recebe também as linhas do **dia anterior** e faz `hoje − ontem` em Python, com o mesmo default `0.0` dos dois lados.
- **Digitação instável nos valores**: o redesenho (após cada save e a cada 1,2 s) devolvia o foco por código, e o handler de `focus` reformatava o texto em digitação, injetando `,00` no meio (`66` → `66,00`; digitar a vírgula gerava `66,,00`). Somado a isso, `paraNumero` trocava só a **primeira** vírgula, então `66,,00` virava NaN e era **gravado como zero** silenciosamente. Corrigido com a flag `restaurandoFoco` (silencia o handler durante a restauração) e `paraNumero` tolerante a texto meio digitado. Como o valor errado era gravado como zero sem avisar, pode haver zeros espúrios de antes da correção.
- **Fuso horário nas datas**: `formatarDataISO` usava `toISOString()` (UTC) — à noite o dia saía errado. Agora usa data local, com `parseDataISO` para o caminho inverso.

## Fluxo de Caixa Projetado

`GET /fluxo-caixa-projetado`. Jan→mês atual é real, do mês atual em diante é projetado pela média dos N meses realizados. Dois tipos de análise (Fluxo de Caixa = todos os grupos; Margem Bruta = grupos 4/5/6 + linha de MB).

**Contas que entram na projeção**: coluna `projetar boolean NOT NULL DEFAULT true` em `contas_gerenciais` (`migrations/adicionar_projetar_contas_gerenciais.sql`). Checkbox na coluna "Proj." do grid (só nas linhas de conta) e também na tela de Contas Gerenciais — os dois gravam no mesmo campo. Desmarcada, os meses projetados saem **em branco** (valor 0, que o template já renderiza vazio) e não somam nos totais. Vale para os **dois** tipos de análise. Endpoint: `PUT /api/contas-projecao`. Ao marcar/desmarcar a página recarrega (totais são calculados no servidor); o estado visual — tipo de análise, analítico/sintético e filtro de grupos — é preservado via `sessionStorage`.

> **Armadilha**: `contas_gerenciais` tem **triggers** que bloqueiam `INSERT` e `DELETE`, e um terceiro que impede alterar as colunas-chave no `UPDATE`. A tabela é alimentada pela importação. Portanto **nada de upsert** nela — só `UPDATE`, e tratar `rowcount == 0` como "conta não existe no cadastro".

## Exclusões de lançamentos

`GET/POST /exclusoes`. No primeiro acesso, sugere o **último** período com dados (`ORDER BY ano DESC, mes DESC LIMIT 1`) — mesmo critério da consulta matricial. Antes não marcava nada e o navegador exibia a primeira `<option>`, que no combo de meses (crescente) era o mês **mais antigo**; além disso a grade não vinha filtrada. A sugestão só entra quando ano e mês vêm ambos vazios.

# Módulo Operações

## Bloquear Movimentações

Botão vermelho no menu de Operações (`OPERACOES/BLOQUEAR_MOVIMENTACOES` 490). Tela `templates/bloquear_movimentacoes.html` (`GET /operacoes/bloqueios`): seletor de mês/ano e um checkbox "Bloqueado" por dia do mês, salvo na hora por `POST /operacoes/bloqueios/alternar`.

- Bloqueio é **por empresa e por data** (`operacoes_bloqueios`, uma linha = bloqueado; desbloquear apaga a linha). `migrations/criar_tabela_operacoes_bloqueios.sql`.
- Botão **"Bloquear tudo até aqui"** em cada linha (`POST /operacoes/bloqueios/bloquear-ate`): fecha aquela data e todas as abertas atrás dela, parando no limite do bloqueio automático. É o atalho para a regra da importação em Saldos; sem ele seria um clique por dia, fins de semana inclusive. Idempotente (`ON CONFLICT DO NOTHING`), e a tela recarrega porque o intervalo pode passar do mês exibido.
- **Bloqueio automático após 10 dias** (`DIAS_LIMITE_BLOQUEIO`, em `services/bloqueios_service.py`): data mais antiga que isso conta como bloqueada esteja ou não na tabela, e o endpoint recusa desbloquear (403). Na tela esses dias aparecem marcados, desabilitados e com o selo "automático". As regras ficam todas nesse serviço (`data_bloqueada`, `datas_bloqueadas`, `datas_bloqueio_pendentes`, `msg_data_bloqueada`) porque Operações e Financeiro precisam da **mesma** conta.
- Data bloqueada não grava mais nada em Informar Medições, Informar Preço de Compra, Informar Compras e Informar Descarregos — as telas continuam abrindo, com aviso e campos desabilitados. A trava real está nos **7 pontos de gravação** (POST das 4 telas, os 2 ajax-salvar e as 2 exclusões), via `data_bloqueada()` / `msg_data_bloqueada()`. Nas exclusões vale a data do **próprio lançamento**, não a data em tela.
- É o que libera a importação dos valores de estoque em Financeiro → Saldos.

## Consulta de Estoques

A consulta grande saiu da rota para `services/estoques_service.py` (`linhas_estoque`, `totais_estoque_rs`): a importação em Saldos usa a **mesma** função, para os números não divergirem com o tempo. O cursor precisa ser `RealDictCursor`.

# Módulo Vendas

## Parâmetros (origem da importação do painel)

`vendas_parametros` (`migrations/criar_tabela_vendas_parametros.sql`), uma linha por empresa. Hoje só `sistema_origem_painel`: `WEBPOSTOS` (EMP010/011/011ADM/012) ou `OCLOSET` (EMP013). Empresa sem linha = WebPostos. Tela em `Vendas → Parâmetros` (`templates/vendas_parametros.html`, permissão `VENDAS/PARAMETROS` 770). Os rótulos saem de `SISTEMAS_ORIGEM_PAINEL`; o selo "Origem: …" nas telas de importação vem do template global `origem_painel_empresa()` (cacheado em `g`).

## Importar Painel — O Closet (EMP013)

`GET/POST /vendas/painel/importar` decide o formato pela origem da empresa: WebPostos segue no fluxo Excel de sempre; `OCLOSET` cai em `importar_painel_ocloset` + `templates/vendas_importar_painel_ocloset.html`.

O arquivo é o CSV "vendas item por pagamento" (`;`, uma linha por item). Lido por `ler_csv_ocloset`:

- **quantidade** = número de linhas
- **valor** = soma de `Total do item` — **não** de `Líquido recebido`, que se repete em todas as linhas da mesma nota (somar a coluna multiplicaria a venda) e vem vazio em itens sem pagamento
- **custo** = soma de `Custo total`; vazio ou zero vira metade do valor do item (equivale a metade do preço unitário por peça)
- **margem bruta** = valor − custo
- **dias** = datas distintas no arquivo (não o intervalo do calendário)

Sem filtro de Status — todas as linhas entram. A projeção do mês é a média diária × dias do mês informado; `dia_base` gravado em `vendas_painel_importacoes` é a quantidade de dias lidos. EMP013 tem uma filial só (cod_filial 1); com mais de uma, tudo vai para a primeira e a tela avisa.
